<task type="checkpoint:human-action" gate="blocking">
  <name>Execute Alpha Channel Audit - Scenario A (Alpha Enabled)</name>
  <what>
    Run 4-6 hour streaming simulation with alpha channel enabled (current default configuration) to establish baseline performance metrics for memory footprint and FPS impact.
  </what>
  <instructions>
    **Pre-Test Setup:**
    1. Clear browser data: Chrome Settings -> Privacy -> Clear browsing data (cached images, localStorage)
    2. Close unnecessary browser tabs/applications to minimize interference
    3. Note hardware specs: Visit chrome://gpu and copy GPU info, note CPU model
    4. Verify config: Open src/config/config.js, confirm `config.performance.alpha.background = true`

    **Test Execution (4-6 hours):**
    1. Open background.html?perf=true in dedicated Chrome window
    2. Press F12 to open DevTools, go to Memory tab
    3. Click "Take heap snapshot" (Baseline T=0)
    4. Record start time in ISO 8601 format: `new Date().toISOString()` in console
    5. Let run for 4-6 hours (window must stay visible - can use machine for other tasks)
    6. Take heap snapshots every 2 hours:
       - At T=2h: Take heap snapshot, note time
       - At T=4h: Take heap snapshot, note time
       - At T=6h: Take heap snapshot (if running 6 hours), note time
    7. After test completes:
       - Record end time: `new Date().toISOString()`
       - In console: `window.perfMonitor.getSessions()`
       - Copy output to text file (alpha-scenario-a-session.json)

    **Data Extraction from Heap Snapshots:**
    1. For each snapshot, record in 03-AUDIT-ALPHA.md:
       - Total Heap size: Look at "Shallow Size" total in DevTools
       - Canvas Memory: Search for "ArrayBuffer" in snapshot, filter by "canvas", sum sizes
       - Detached Nodes: Look for "(Detached DOM tree)" in snapshot, count instances
    2. In DevTools Memory panel, compare snapshots:
       - Select snapshot pair (T=0 vs T=6h)
       - Look for memory growth patterns
       - Check for detached DOM nodes (leak indicator)

    **Populate 03-AUDIT-ALPHA.md:**
    1. Fill "Scenario A: Alpha Enabled" section:
       - Session Summary JSON (from window.perfMonitor.getSessions())
       - Heap Snapshots table with times and memory values
       - Notes section: Any visual issues, crashes, anomalies observed
    2. Record test environment details:
       - Browser version: `navigator.userAgent` in console
       - Platform: `navigator.platform` in console
       - Hardware: CPU/GPU from chrome://gpu
  </instructions>
  <expected>
    Scenario A data in 03-AUDIT-ALPHA.md showing:
    - Session summary with avgFPS, peakMemoryMB, droppedFrames for 4-6 hour run
    - Heap snapshot table with memory values at T=0, T=2h, T=4h, T=6h
    - No crashes or visual artifacts during test
    - Memory usage trend: stable (good) or growing (potential leak)

<task type="checkpoint:human-action" gate="blocking">
  <name>Analyze Results and Complete Audit Report</name>
  <what>
    Compare Scenario A vs Scenario B measurements, calculate deltas, determine if alpha channel optimization is needed based on conservative streaming thresholds, and write recommendations in 03-AUDIT-ALPHA.md.
  </what>
  <instructions>
    **Analysis Section (in 03-AUDIT-ALPHA.md):**

    1. **Memory Comparison:**
       - Calculate average memory for each scenario:
         - Scenario A: Average of (T=2h + T=4h + T=6h) / 3
         - Scenario B: Average of (T=2h + T=4h + T=6h) / 3
       - Calculate delta: `(Scenario A - Scenario B) / Scenario A * 100` = memory reduction %
       - Compare to research prediction: 15-25% reduction expected
       - Document actual reduction: "Disabling alpha reduced memory by X%"

    2. **FPS Comparison:**
       - Scenario A avgFPS: (from session summary)
       - Scenario B avgFPS: (from session summary)
       - Calculate delta: `(Scenario B - Scenario A) / Scenario A * 100` = FPS improvement %
       - Check threshold: Is improvement >5%? (CONTEXT threshold)
       - Document: "Disabling alpha improved FPS by X%"

    3. **Stability Analysis:**
       - Memory growth over time:
         - Scenario A: Compare T=0 vs T=6h (growth % = leak indicator)
         - Scenario B: Compare T=0 vs T=6h
       - Detached nodes: Any growth indicates potential leak
       - Dropped frames: Compare counts between scenarios
       - Document: "Both scenarios stable" OR "Scenario X showed memory growth"

    4. **Threshold Check:**
       - Memory threshold: <300MB steady-state (from CONTEXT)
       - FPS drop threshold: <5% (from CONTEXT)
       - Stability threshold: 8+ hours without crashes
       - Document: "Scenario A met/exceeded thresholds" with specific values

    **Findings Section:**
    Write 3-5 bullet points summarizing:
    - Actual memory reduction from disabling alpha (% and MB)
    - Actual FPS improvement from disabling alpha (% and absolute)
    - Whether current alpha-enabled config meets streaming thresholds
    - Any unexpected behaviors or anomalies observed
    - Visual quality assessment: Any artifacts when alpha disabled?

    **Recommendations Section:**
    Based on threshold analysis, write clear recommendation:

    **IF Scenario A (alpha enabled) MEETS thresholds (<300MB, FPS stable):**
    "Recommendation: Keep alpha enabled. Current configuration meets conservative streaming thresholds with X MB memory and Y fps. Alpha provides flexibility for Phase 4 visual enhancements. Memory reduction from disabling (Z%) does not justify losing alpha channel capability."

    **IF Scenario A EXCEEDS thresholds (>=300MB OR >5% FPS drop):**
    "Recommendation: Disable alpha for background scene. Measurements show X MB memory (exceeds 300MB threshold) with Y% FPS drop. Disabling alpha reduces memory by Z MB and improves FPS by W%, bringing performance within acceptable streaming targets. Implementation: Set config.performance.alpha.background = false."

    **Executive Summary:**
    Write 2-3 sentence summary at top of document:
    - What was tested (alpha enabled vs disabled, 4-6 hour runs)
    - Key finding (memory delta, FPS delta, threshold status)
    - Recommendation (keep or disable alpha)

    **Additional Context (from user note in instructions):**
    - User reported "performance worse when GPU acceleration OFF"
    - Add note in Findings: "GPU acceleration should remain enabled - user testing confirmed performance degradation with GPU OFF"
    - Consider adding GPU ON/OFF comparison to "Future Work" section if time permits
  </instructions>
