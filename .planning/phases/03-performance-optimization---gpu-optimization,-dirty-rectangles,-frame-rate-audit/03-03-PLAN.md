**TIME REQUIRED:** 8-12 hours total (two 4-6 hour test runs can overlap with other work - browser window must stay visible but machine usable)

**Preparation:**
1. Ensure dev server running: npm run dev (from project root)
2. Open Chrome/Chromium (not Firefox - OBS uses Chromium engine)
3. Clear browser cache: DevTools > Application > Clear storage > Clear site data

**Scenario A: Alpha Enabled (Baseline)**

1. Verify config: Open src/config/config.js, confirm config.performance.alpha.background = true
2. Open in dedicated Chrome window: http://localhost:5173/src/background/index.html?perf=true
3. Verify performance overlay appears (top-right corner, showing FPS/Memory)
4. Open DevTools (F12) > Memory tab
5. Click "Take snapshot" button → label it "Baseline-Alpha-Enabled-T0"
6. Note start time (ISO 8601 format: YYYY-MM-DDTHH:MM:SSZ)
7. Minimize DevTools (keep tab visible - DON'T background the window)
8. Set timer for 2 hours
9. Every 2 hours:
   - Reopen DevTools > Memory
   - Take heap snapshot → label "Alpha-Enabled-T{hours}h"
   - Record snapshot stats in AUDIT-ALPHA.md table:
     - Total Heap: Look at top of snapshot (e.g., "23.4 MB")
     - Canvas Memory: Click "Statistics" view, find ArrayBuffer size
     - Detached Nodes: Search for "Detached" in snapshot
10. After 4-6 hours total:
    - Open DevTools console
    - Run: copy(JSON.stringify(window.perfMonitor.getSessions(), null, 2))
    - Paste into AUDIT-ALPHA.md "Session Summary" section
11. Note any crashes, visual artifacts, or issues in "Notes" section

**Scenario B: Alpha Disabled (Optimized)**

1. Edit src/config/config.js: Set config.performance.alpha.background = false
2. Reload browser (clear cache again)
3. Repeat steps 2-11 from Scenario A
4. Label snapshots "Alpha-Disabled-T{hours}h"

**Data Analysis:**

After both scenarios complete:
1. Fill in Analysis section of AUDIT-ALPHA.md:
   - Calculate memory delta: Scenario A peak - Scenario B peak
   - Calculate FPS difference: (Scenario A avg - Scenario B avg) / Scenario A avg * 100
   - Note if memory stayed under 300MB threshold
   - Note if FPS stayed above 55fps floor
2. Complete Findings section:
   - Answer YES/NO for each finding
   - Document actual numbers
3. Write Recommendations section:
   - If memory >300MB OR FPS drop >5% in Scenario A: Recommend "OPTIMIZE IN PHASE 3"
   - If both within thresholds: Recommend "DEFER TO PHASE 4" (preserve flexibility)
   - Provide rationale based on data

**Expected Results:**
- Scenario A (alpha enabled): ~200-250MB memory, 58-60 FPS (based on Phase 2 stress tests)
- Scenario B (alpha disabled): ~150-200MB memory (15-25% savings), 58-60 FPS (minimal FPS change expected)
- No crashes or memory leaks (Phase 1 LRU cache fixes should prevent unbounded growth)

**Troubleshooting:**
- If FPS drops significantly (<50fps): Check system load (close other apps), verify no throttling
- If memory grows continuously: Check for detached DOM nodes (memory leak - should NOT happen post-Phase 1)
