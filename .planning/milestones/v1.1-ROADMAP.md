# Milestone v1.1: Shade Component

**Status:** ✅ SHIPPED 2026-01-20
**Phases:** 5-7
**Total Plans:** 7

## Overview

Add shade component for major stream events with semi-transparent curtains and scrolling text. The shade provides a commanding celebratory presence for raids, gift subs, and other significant stream moments.

## Phases

### Phase 5: Text Animation Core

**Goal**: Users can see large scrolling text with dynamic hold duration based on readability
**Depends on**: Phase 4
**Requirements**: TEXT-01, TEXT-02, TEXT-05, CONFIG-01, CONFIG-02, CONFIG-04, CONFIG-05, TEST-01
**Plans**: 3 plans

**Success Criteria** (what must be TRUE):
1. Text renders on canvas with explicit fillStyle for OBS browser source compatibility
2. Hold duration calculated dynamically from text length using reading speed baseline (200ms/word)
3. Text is fully readable - minimum duration enforced regardless of text length
4. Shade scene accepts URL parameters (?text, ?color, ?duration) for OBS integration
5. Custom fonts load before text measurement to prevent race conditions

Plans:
- [x] 05-01: Text core & URL configuration
- [x] 05-02: Scrolling animation & timing
- [x] 05-03: Integration & testing

**Completed:** 2026-01-19

### Phase 6: Curtain Integration & Synchronization

**Goal**: Text and curtains animate as unified "shade" effect with synchronized three-phase lifecycle
**Depends on**: Phase 5
**Requirements**: CURTAIN-01, CURTAIN-02, CURTAIN-03, CURTAIN-04, CURTAIN-05, TEXT-03, TEXT-04, TEXT-06, TEXT-07, CONFIG-03, PERF-04, TEST-02
**Plans**: 2 plans

**Success Criteria** (what must be TRUE):
1. Semi-transparent curtains enter from top and bottom edges with smooth easing
2. Text "flies in" with curtains during enter phase, "flies out" during exit phase
3. Text scrolls horizontally during hold phase with constant speed
4. Text renders above curtains (always visible, not clipped)
5. Text and curtains synchronized via single phase controller - no desynchronization

## Milestone Summary

**Key Decisions:**

- 05-01: Reading speed 200ms/word (5 words/sec) calibrated for stream event pacing
- 05-01: 96px bold Jost font for commanding celebratory presence during stream events
- 05-01: Font Loading API integration prevents race condition (document.fonts.ready → init() → measureText)
- 05-02: 3-second minimum hold duration enforced regardless of text length for short message readability
- 05-02: Word count (not character count) for duration calculation correlates with reading comprehension time
- 05-03: Velocity-first animation architecture eliminates phase boundary discontinuities (< 0.01 px/s at transitions)
- 05-03: Position updated each frame: x -= velocity * deltaTime (not position interpolation with easing)
- 06-01: Opacity 0.5 (middle of 0.4-0.6 range) provides balanced semi-transparency for curtains
- 06-01: Canvas clipping (ctx.clip()) prevents bars from rendering outside curtain boundaries during enter/exit
- 06-02: Critical rendering order (curtains first, text last) ensures text always visible above curtains
- 06-02: Shared totalDurationMs calculated once from text length prevents desynchronization
- 07-01: drawImage() replaces fillText() in draw loop for 10-20x speedup (PERF-01)
- 07-01: hsla() gradient colors with opacity parameter instead of globalAlpha for GPU efficiency (PERF-03)

**Issues Resolved:**

- Velocity discontinuities at phase boundaries (THREE iterations to solve)
- Font loading race conditions causing incorrect text measurement
- Text alignment issues with offscreen canvas rendering
- Curtain synchronization challenges with text animation lifecycle

**Issues Deferred:**

- OBS validation testing (performance script implemented but not executed)
- GPU usage measurement (hsla() optimization implemented but not validated)
- 30-minute stability testing (infrastructure ready, testing deferred)

**Technical Debt Incurred:**

- OBS validation protocol documented but never executed (6 test scenarios defined)
- Performance validation script available (window.perfValidation.runAll()) but no empirical measurements
- Font loading async callback added but could be simplified with top-level await
