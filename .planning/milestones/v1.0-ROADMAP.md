# Milestone v1.0: Foundation

**Status:** ✅ SHIPPED 2026-01-18
**Phases:** 1-4
**Total Plans:** 22 (18 complete + 4 gap closure deferred)

## Overview

This roadmap transforms a working but fragile brownfield codebase into a maintainable foundation for stream graphics. The journey progresses from fixing critical memory leaks and timing bugs that cause crashes during long streams, through comprehensive testing that prevents AI coding regressions, to performance optimization and visual polish. Each phase delivers observable improvements to stability, maintainability, and visual consistency while preserving the core value: flawless background animation performance.

## Milestone Summary

**Decimal Phases:** None (no urgent insertions required during v1.0)

**Key Decisions:**
1. LRU cache with bounded size (maxSize=50) prevents memory exhaustion over long streams
2. Delta-time normalization provides frame-rate independence across 30/60/120Hz displays
3. AnimationLifecycle with AbortController pattern ensures proper cleanup on OBS reload
4. Centralized config.js with documented coordinate system prevents AI positioning bugs
5. Property-based testing with @fast-check/vitest catches edge cases automatically
6. Brightness multiplier (0.8) applied consistently across all scenes for visual harmony
7. Millisecond-based timing with shared defaults and per-scene overrides for maintainability
8. Phase 3 validation deferred: infrastructure complete, empirical validation post-milestone

**Issues Resolved:**
1. Memory leaks from unbounded offscreen canvas cache (Phase 1: LRU eviction)
2. Frame-rate dependent timing causing inconsistent animation speeds (Phase 1: delta-time)
3. Event listener leaks on OBS scene reload (Phase 1: lifecycle cleanup)
4. Magic numbers scattered across codebase (Phase 1: centralized config)
5. AI coding regressions from position changes (Phase 2: coordinate contract tests)
6. Color test failures from hex normalization (Phase 2: cssColorToHex)
7. Brightness inconsistency between scenes (Phase 4: 0.8 multiplier across all)
8. Mixed timing approaches (frame-based vs time-based) (Phase 4: millisecond unification)

**Issues Deferred:**
1. Alpha channel audit execution (03-07) - infrastructure ready, measurement not collected
2. Frame rate audit execution (03-08) - infrastructure ready, stress scenarios not run
3. Dirty rectangle empirical validation (03-09) - implementation complete, disabled pending validation
4. Long-duration stability validation (03-10) - monitoring ready, 4-6 hour test not performed

**Technical Debt Incurred:**
- Phase 3 validation work deferred (4 items): Alpha audit, frame rate audit, dirty rectangle validation, long-duration stability test. All infrastructure complete and tested. Validation can be performed as standalone work or as part of Phase 5.
